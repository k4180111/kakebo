# Kakeibo — учёт личных финансов

Локальное веб-приложение для ведения бюджета по методу какебо: определить доход и цель накоплений, записывать расходы и регулярно анализировать привычки.

## Технологии

- **React + TypeScript + Vite** — интерфейс и быстрая локальная разработка.
- **IndexedDB** — локальная база данных в браузере, без сервера и регистрации.
- **Web Crypto API** — клиентское шифрование резервных копий AES-256-GCM; ключ выводится из пароля через PBKDF2-SHA-256.
- **Google Drive API (следующий этап)** — хранение и синхронизация зашифрованной копии в приватной папке приложения (`appDataFolder`).

Денежные значения сохраняются целым числом копеек, чтобы избежать ошибок округления. Локальная база доступна только в том браузере и профиле, где приложение использовалось. Зашифрованную копию следует хранить отдельно, а пароль — не забывать: восстановить его невозможно.

У каждой расходной записи категория и сфера — два независимых признака: категория описывает вид покупки, а сфера — её место в методе какебо. Доходам сфера не назначается. В сохранённых ранее расходах, созданных до появления сфер, историческое значение не угадывается: такие суммы видны отдельно как «Сфера не указана».

Категории расходов, категории доходов и сферы настраиваются отдельными списками. Переименование категории обновляет название в уже существующих операциях; переименование сферы сохраняет её идентификатор и привязку операций. Используемые категории и сферы нельзя удалить, пока на них ссылаются операции. Настройки входят в новые резервные копии; старые копии без настроек сохраняют текущие списки при восстановлении.

## План разработки

### Этап 1 — приватное локальное приложение (текущий MVP)

- [x] Главная сводка: доходы, расходы, лимит и остаток на месяц.
- [x] План месяца: доход, обязательные траты и цель накоплений.
- [x] Добавление и удаление доходов и расходов по категориям.
- [x] Независимый выбор категории расходов и сферы какебо: нужды, желания, культура или непредвиденное.
- [x] Редактирование категорий доходов и расходов, а также сфер в настройках.
- [x] История операций, переключение месяца и отдельная аналитика по категориям и сферам.
- [x] Рефлексия по четырём вопросам какебо.
- [x] Локальное сохранение данных, настроек списков и пароль-защищённый файл резервной копии.

### Этап 2 — подготовка Google Drive

- Создать проект Google Cloud и OAuth client ID для веб-приложения.
- Вход через Google Identity Services без собственного сервера.
- Перед загрузкой шифровать данные в браузере; в Drive отправлять только шифротекст.
- Использовать один файл в `appDataFolder`, хранить соль и параметры KDF рядом с шифротекстом, но никогда не сохранять пароль.
- Проверять версию файла и время изменения; при конфликте на двух устройствах не перезаписывать данные молча, а предложить выбрать копию или сохранить обе.
- Добавить явные действия «Синхронизировать», «Загрузить из Drive» и показать время последней успешной синхронизации.

### Этап 3 — надёжность и удобство

- Автотесты расчётов бюджета, IndexedDB и формата зашифрованного файла.
- PWA-режим, установка на устройство и работа без сети.
- Импорт/экспорт CSV и проверка восстановления резервной копии.
- Доступность интерфейса, мобильная адаптация и понятные сообщения об ошибках.

## Запуск

Требуется Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev
```

Проверка production-сборки:

```bash
npm run build
```

## Шифрование резервной копии

В «Настройки» → «Зашифрованная копия» можно создать файл `.enc` или восстановить данные из него. Шифрование выполняется в браузере с AES-256-GCM и отдельной случайной солью для каждой копии. Используйте надёжный пароль длиной не менее 12 символов и храните его отдельно от файла.

Google Drive пока не подключён: для безопасной синхронизации сначала нужно настроить OAuth client ID и проверить обработку конфликтов между устройствами.
